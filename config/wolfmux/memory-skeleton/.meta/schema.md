# Memory tree: the format

One team's private memory. `bin/mem` writes it; this file says what each part holds.
Keep it current when the format changes.

## The tree

```
<root>/                      mode 700, files 600 (mem check re-checks)
  MEMORY.md                  TOC + legend, auto-loaded by Claude Code. <= 5,000 bytes, <= 80 lines,
                             ONE link per line, <= 120 chars per line. Generated by `mem check` from the file headers.
  core/card.md               GENERATED by `mem boot`, <= 2,000 bytes. Never hand-edited.
  core/boot.md               hand-written restart checklist template, <= 2,000 bytes.
  state/open-asks.json       [{id, who, what, opened, waiting_on, next_check, status}]
  state/watches.json         threads, PRs, envs, releases watched, with cursors
  state/cursors.json         read markers in ONE place (slack_dm, gmail, fellow, beads_<repo> ...)
  state/crons.json           every cron/watcher to re-create: name, schedule, prompt_file, enabled
  state/machine.json         current machine start/stop lines and when set
  rules/ people/ teams/ topics/   one markdown file per item, with the header below
  ledger/decisions-YYYY-MM.md   append-only; the owner's words VERBATIM with UTC time and source
  ledger/sends-YYYY-MM.md       time, to, channel, permalink or bead id, 1-line subject (no body)
  ledger/asks-YYYY-MM.md        asks opened and closed
  ledger/sweeps-YYYY-MM.jsonl   one JSON line per sweep
  archive/index.md           one line per archived file: date, from, reason
  archive/YYYY-MM/...        same sub-structure
  bin/mem                    the tool (bash + python3 -I)
  .meta/schema.md            the format spec (this file)
  .meta/drain.log            what moved when and why; retention basis per backup
  .meta/backups/             tars before each drain and migration, mode 600, kept 7 days
  .meta/jev/                 request/response JSON of every Jev call (audit)
```

Also under `.meta/`: `lock` (the one writer lock; `boot` never waits for it and, while another
writer holds it, prints a fresh card without saving it), `shared-folder` (the shared project
folder's path, one line), `digest-pending.md` (drain candidates waiting for the owner),
`migrate-<UTC>.md` (the report of a real migration). Empty folders carry a `.keep` file;
mem ignores it.

Which tree mem works on: `--root <dir>` (before the command or after it; two different ones
are a usage error), else `$MEM_ROOT`, else the folder above `bin/mem`. When `bin/mem` is a link
and the folder above the link holds `.meta/`, that folder is the tree (a link into a repo's
skeleton never writes the repo); otherwise (a link at `~/.local/bin/mem`) it is the folder
above the real script. A writer (every command but recall, status and help) refuses a tree
whose path holds `/memory-skeleton/`, the repo's shipped copy: "this is the shipped skeleton;
pass --root to use it". Only `--root` naming it lets a writer in; `$MEM_ROOT` does not.

## File header (every file in rules/ people/ teams/ topics/)

```
---
name: <slug>
region: rules | people | teams | topics
keywords: a, b, c
summary: one line, <= 160 chars
links: [[other-name]], [[another]]
importance: 1..5          5 = never auto-drain
authority: decisions-2026-10#2026-10-09T13:50Z     (rules: REQUIRED; the ledger line that set it)
last_confirmed: YYYY-MM-DD
status: live | superseded:<name>
repo_ref: fe:src/features/x/agent-log/0007.md AFD-2129     (optional, topics only; chunk path + Jira key, never an index line)
---
```

- The body is every byte after the closing `---` line, untouched. mem adds no blank line.
- A hand-written header may hold blank lines, `# comments`, `- items`, indented continuations
  and `key:value` without the space. A rewrite changes only the lines whose value changed and
  keeps the file's line ends (CRLF stays CRLF).
- `name` is a slug (`a-z 0-9 _ . -`, at most 80 characters) and matches the file name.
- `authority` is `decisions-YYYY-MM#<anchor>` (a block in the decisions ledger, live or
  archived) or `shared:<path>` (a rule that lives in the shared folder). Malformed is a
  problem; not found is a warning.
- Optional fields mem writes: `superseded_on: YYYY-MM-DD` (set by `add --supersedes`; drain
  ages superseded files from it), `pointer: <abs path>` (a pointer file, in any region: an
  item whose text lives in the shared folder; `decide --shared` refreshes its
  `last_confirmed`), `origin:`
  (where `check` or `migrate` found the file).
- Superseded files are left out of MEMORY.md.

## MEMORY.md

Title line `# Memory (checked <UTC> by mem check, <bytes> bytes)`, then `## Legend`,
`## Boot (every start)`, one section per region with one line per live file
(`- [name](region/file.md) summary-cut-to-fit`, newest `last_confirmed` first within rules;
a long name is cut in the link text so the summary keeps 20 characters, never in the path),
and `## Ledger pointers` (this month's ledger files with line counts). A line with more than
one link (a hub of hubs) is a problem.

The legend is one line per part of the tree (core, state, rules, people/teams/topics, ledger,
archive) and one boot line, no examples: at most 500 bytes.

Index caps, in lines per region section: rules 14, people 6, teams 4, topics 7. The sum, with
every line at its 120-character cap:

| part | bytes |
| --- | --- |
| 31 region lines x 121 (120 characters + newline) | 3,751 |
| legend and boot line | <= 500 |
| title `# Memory (checked <UTC> by mem check, NNNN bytes)` | 62 |
| five headings (Rules, People, Teams, Topics, Ledger pointers) | 57 |
| four ledger pointers, ~58 each | ~231 |
| total | ~4,600 of 5,000; 50 of 80 lines |

So a full tree fits without the byte shrink below; the shrink is the exception, for lines of
wide characters (an `é` is 2 bytes, most CJK 3). Rules come newest
first; people, teams and topics most important first, then newest `last_confirmed`. A region
with more live files than its cap shows the first ones and ONE line
`- N more <region>: mem recall <words>`. If the index still passes 5,000 bytes, one region
shows one entry fewer per pass: topics first, then teams, people and rules. Topics, teams and
people go down to no entry (only the `N more` line), rules to one. When every region is at
that floor and the bytes still pass the cap, `check` WARNs `index over budget by N bytes`.
A cut region is a WARN in `check`, never a problem.

`add`, `drain` and `unarchive` regenerate MEMORY.md and the card at once but do not run the
full lint (keyword overlap, ledger references, modes, auto-memory filing): that is `mem check`.

## Ledger formats (append-only)

- decisions: one block per decision.
  ~~~
  ## 2026-10-09T13:50Z          (a second one in the same minute gets -2, -3 ...)
  slug: <slug>
  source: chat | slack:<ts> | bead:<id>
  bytes: <length of the quote>
  ```                           (3 backticks, or one more than the longest backtick run in the quote)
  <the quote, byte for byte>
  ```
  ~~~
  The authority ref is `decisions-YYYY-MM#<anchor>`, the anchor being the `##` heading text.
- sends: `- <UTC minute> | to: <who> | channel: <c> | ref: <permalink or bead> | <subject>`
- asks: `- <UTC minute> | open | <id> | who: <who> | waiting on: <who> | <what>` and
  `- <UTC minute> | close | <id> | <note>`
- sweeps: one JSON object per line: `time, inboxes, asks_touched, free_pct, swap_gb, load`.
  Lines older than 14 days are archived; one summary line per day stays:
  `{"time": "<day>T00:00Z", "day", "summary": true, "sweeps", "inboxes_max", "asks_touched"
  (the day's sum), "free_pct_min", "swap_gb_max", "load_max"}`.
- a migrated state key (`mem migrate`, a `state:` row into a ledger file) is appended as
  `## migrated state:<key> at <UTC minute>`, then the value pretty-printed in a ```` ```json ````
  fence. A re-run finds the same block (whatever its minute) and appends nothing.
- In the decisions ledger, the fence `decide` writes (the line after `bytes: N`) holds exactly
  N bytes of quote: a `## <time>` or `slug:` line inside them never starts a block. N is
  trusted only when the line those N bytes reach (N + 1 for a quote without a final newline)
  really is a closing fence. Any other open fence (a stray one, or a decide fence whose N is
  too small or too large) ends at its closing fence or at the next `## <time>` line that is
  followed by a `slug:` line, so it never swallows the decisions after it. `mem check` WARNs
  once per block whose `bytes:` count does not match, naming its time. `mem erase` counts
  `bytes:` again for every quote it edits. `mem decide` refuses (exit 64, "anchor taken") an
  anchor whose `## <anchor>` line sits outside every quote but starts no block (a damaged
  block holds it). `mem migrate` refuses a decisions payload that leaves a fence open, holds a
  damaged block, or would cost a decide block appended after it its anchor.
- `mem ask close` takes any id of `[A-Za-z0-9._-]` (migrated asks keep theirs); `mem ask
  open` still needs a slug.

## Archive

- `archive/index.md`: `- <date> <where it is now> from <where it was>: <reason>`.
- `archive/YYYY-MM/<region>/<file>`, `archive/YYYY-MM/ledger/<file>`. A ledger month that is
  archived again is appended to the archived copy.

## .meta/drain.log

One line per event, `<UTC second> <event>`: `backup .meta/backups/<name> sha256=<hex>
basis=<retention basis>` (a tar rebuilt by erase adds `(rebuilt by erase)`), `prune ...`,
`archive <from> -> <to>: <reason>`, `rule 1: ...`, `rule 3: ...`, `rule 4: ...` (Jev answers
and failures), `unarchive <from> -> <to>`, `erase on the owner's word: erase id <8 hex> ...`
(a random id that erase also prints; never the subject, never a hash of it),
`purge on the owner's word: ...`.

## Backups

`.meta/backups/<YYYYMMDDTHHMMSSZ>[-n].tar`, mode 600, the tree minus `.meta/backups` and the
lock. The routine basis is `kept 7 days`: only those are pruned, after 7 days. Any other basis
(the migration rollback tar says "on the owner's word") is never pruned automatically. A tar
with no `basis=` line in drain.log (lost or unreadable) is kept too, never taken as routine;
when erase rebuilds such a tar it logs `basis=unknown (no log line; kept)`.

## Jev (drain rule 4)

A rule-4 candidate is archived only when Jev answers archive with probability >= 0.7. Jev gets
slug, region, keywords, importance, days since last_confirmed, days since last reference and
the size in bytes, nothing else; every token that matches a people/ file name (or a part of it
split on `-`), or holds such a part of 3 or more letters (`danasmith`), is replaced by
`person`, accents folded first (`Renée` is `renee`). `.meta/jev/<UTC>-<slug>.json` keeps what was sent and
what came back: `time, url, attempts, status, error, sent, response`, and `local` (`{"file":
"<region>/<name>.md"}`, the real path, which never left the machine). Any error, or an answer of the wrong shape: the candidate goes to
`.meta/digest-pending.md`; nothing moves. Errors are logged by type name only.

The key: `MEM_JEV_KEY`, else the Keychain item `typesafe-api-key`, which is sent only to the
default URL `https://api.typesafe.ai/v1/systemone` (a custom `MEM_JEV_URL` needs
`MEM_JEV_KEY`). A key outside printable ASCII (a space, a newline) is never sent: "jev key
rejected (format)". Test hooks: `MEM_NOW` pins the clock; with it set, `drain` refuses and
backup pruning is skipped unless `MEM_TEST=1`.

## Erase (mem erase, on the owner's word)

The subject matches as a whole word (`tom` finds `Tom`, not `tomorrow` or `custom`). Both
sides are normalised the same way: NFC, then the accent fold Jev masking uses, lower case
(`José`, its decomposed form and `Jose` are one name), and the subject's words match across
any run of space, `-`, `_` or `.` (`Tom Smith` finds `people/tom-smith.md` and
`[[tom-smith]]`). A subject under 3 letters and digits, or a JSON literal (`true`, `false`,
`null`, a number), is refused with exit 64. A path matches on its file stem only, never a folder name or an extension, and
only for a file erase removes whole (below): mem's own files (drain.log, digest-pending.md,
shared-folder, migrate reports) are edited line by line, never dropped for their name, and
the words of their names (drain, digest, pending, folder, migrate, role, jev, log, schema,
card, boot, index) and the singular forms (team, topic, ask, decision, sweep, send, rule,
person) are refused as subjects. JSON (a
`.json` file, each `.jsonl` line) is decoded before it is matched, so a name stored as
`\uXXXX` escapes is found; values count at any depth, and so do a state object file's
top-level keys (they name its entries). Any other key (a field name like `free_pct`, a
nested key) erases nothing: the file is listed once as `left behind: <path> (key)`, and the
count leaves it out. mem writes every JSON with the characters themselves, never escapes.
The subject needs 3 characters and a letter, and is not a word every tree holds (a header
field, a folder, a ledger label, a common word). What it does:

- a people/, teams/ or topics/ file (live or archived), or a `.meta/jev/` audit file, that
  names it: removed whole; the listing says why, `(stem)` or the first line that names it
  (cut to 80 characters);
- a rules file (rules/role.md too, live or archived): edited line by line, never dropped, as
  each carries an authority. A header line keeps its field (`summary: [erased ...]`); the
  `name:` line and the file name stay and are listed as `left behind: <path> (file name)`;
- a ledger, index or log line: replaced by `[erased <YYYY-MM-DD> on owner's word]`
  (`{"erased": "<YYYY-MM-DD> on owner's word"}` in a `.jsonl` file);
- a `backup ... basis=` line in drain.log: never replaced; the subject is replaced inside its
  basis text only and the rest of the basis stays, so a tar kept on the owner's word stays
  non-routine and is never pruned. A hit elsewhere in the line (its time, tar name or sha256)
  is listed as `left behind: .meta/drain.log:<n> (backup line)`;
- a state entry: removed;
- any other JSON file (a migrated archive copy): each value that names it becomes
  `[erased <YYYY-MM-DD> on owner's word]`, and the file stays valid JSON;
- each backup tar under `.meta/backups/`: rebuilt the same way. Pre-migration tars under
  `~/.wolfmux/backups/` are listed, never changed.

`.meta/schema.md` and `bin/` ship with mem and are never edited, live or in a tar.
Without `--confirm` it lists every item and the count; `--confirm <count>` erases only when
the listing still has that many items. No backup is made first (it would hold the subject).

## Migration (mem migrate)

The mapping CSV has one row per item: `source,source_type,dest,region,action,hold,name,
keywords,summary,importance,authority,links,repo_ref,notes`. What a row carries:

- a file (`<path>` under --from, `rules:<file>` under --rules-from, `archive:<file>` under
  --from, `claude-mem:<path>` under --claude-mem-from, default
  `~/claude-mem-export-2026-10-22`): its bytes; going to a region, only what follows its own
  frontmatter. source_type is `file`, `rules-file`, `archive-file` or `claude-mem`. A leading
  `---` block is frontmatter only when its FIRST line is `key: value` and every line in it is
  `key: value`, an indented continuation, a `- item`, a `# comment` or blank; otherwise (a
  block of only headings and lists, or one with prose) the whole source is the body. A
  stripped frontmatter's `description` is kept as the `source_description:` header field.
  `hub:<file>#<n>`: line n of that file.
- `state:<key>` (a key of --state): to `state/<file>.json#<key>` or a ledger file, the JSON
  value; to `<region>/<name>.md`, the value's text is the body (a string as is, any other
  value pretty-printed with indent 2 and sorted keys; no newline added).

A region dest gets its header from the row, and its body's sha256 is checked like a file's.
Verification re-reads every file source: its sha256 (shown as `raw`) must be unchanged, and
the placed body must be the raw source minus exactly the stripped block. Rows that place the
same body are each found once at their own dest.
`region` is the dest's folder (empty means the same). A `pointer` row writes a pointer file
into any region folder (`pointer: <abs path>`, authority `shared:<path>` unless the row gives
one, body `Pointer: <path>` and the summary); on a pointer row `region: pointer` also means
the dest's folder. A state key is never a pointer.

The report has one line per row with its status: copy, pointer, hold (the map holds it),
skip, refused (the row breaks this contract; the reason says what to change) or exists (an
earlier run placed it). It ends with `## Summary`: the counts by status, then the refusal
reasons with their values taken out, each with its count and line numbers.

A dest is a plain path in the tree as written: no leading slash, no `.` or `..` segment.
`--from`, `--rules-from` and `--claude-mem-from` may neither lie inside the root nor hold it.
Several rows may append to one ledger month; any other dest takes one row. A ledger row whose
payload the ledger already holds as whole lines (from a line start to a line end, never part
of a longer line) is `exists`, so a re-run appends nothing; verification counts it the same
way, and a state key in the ledger by its whole `## migrated` block, so a short value (`[]`,
`true`) is never counted where it merely appears. The month's archived copy
(`archive/<m>/ledger/<file>`, where drain rule 2 moves it) counts as the ledger too, and a
region or pointer dest that is missing but listed in `archive/index.md` (drain moved it) is
`exists`, "placed earlier, archived": a re-run after a drain places nothing twice. A
real run that refused any row writes its report, then exits 1 unless `--allow-refused` is
given; a dry run exits 0. A re-run in the same second writes `migrate-<UTC>-2.md`.
